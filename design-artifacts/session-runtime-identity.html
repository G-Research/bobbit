Implementation notes and consistency rationale

Placement

  • Model picker: add the runtime badge to the existing right-hand badge cluster, before the provider badge. Do not add a filter, field, row, or selector.
  • Live and archived sessions: show the same compact identity beside the session title and existing model button. Preserve it in read-only/archived presentation and on continue/fork outcomes.
  • Audit: render runtime as a dedicated field/column because this surface optimizes for unambiguous inspection rather than minimum chrome.

Derivation and fallback

  • modelProvider === "claude-agent-sdk" → Claude Agent SDK; every other provider, including anthropic, → Pi.
  • A legacy persisted row without runtime presents as Pi. Do not show “unknown”, because that would contradict the preserved runtime default.
  • An unavailable SDK provider/model keeps the saved Claude Agent SDK badge, adds explicit “Unavailable” text and a reason, and disables selection. Never silently relabel or downgrade it to Pi.

Primitive match

  • The picker retains the existing ModelSelector 400px width, header/search/filter stack, 16px row gutters, outline provider badge, capability icons, disabled opacity, hover fill, and selected-row accent.
  • The header follows the existing session title + goal subtitle hierarchy; the footer follows the 11–12px stats bar and ghost model button. The runtime badge is metadata, not a primary action.
  • The badge reuses the outline-badge grammar: 10px semibold text, 20px minimum height, pill radius, token border/background, tooltip, and an accessible full label. It introduces no new colour category.

Accessibility and responsive behavior

  • Runtime is always written in text. The icon is decorative; status uses text plus symbol. All interactive states provide native keyboard focus.
  • On narrow layouts, the long SDK label truncates visually but remains available in title/aria-label. Audit content becomes horizontally scrollable rather than collapsing identity fields.
  • Loading should retain existing skeleton/loading treatment. Empty search results use the existing centered muted message. Unavailable rows remain visible only when they represent the current/saved model; ordinary unavailable catalogue rows may retain current registry sorting rules.
